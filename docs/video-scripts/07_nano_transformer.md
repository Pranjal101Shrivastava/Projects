## [0:40] What's actually in it

> **On screen —** the architecture panel

The architecture is the modern decoder stack, written out by hand.

4 layers. 6 attention heads. A model dimension of
192, a feed-forward width of 512, and a context window of
128 characters. Dropout at 0.1.

Four pieces worth naming, because each one is a specific choice rather than a default.

**Rotary position embeddings.** Instead of adding a position vector to the input, you rotate
the query and key vectors by an angle proportional to position. The dot product between two
tokens then depends on their *relative* distance, which is the thing attention actually
wants to know.

**SwiGLU.** The feed-forward block splits into two paths, one gated by the other. It costs
more parameters per layer than a plain ReLU network and consistently performs better at the
same budget.

**Pre-normalisation.** LayerNorm goes *before* each sublayer rather than after. That keeps a
clean residual path from the loss all the way to the first layer, and it's the difference
between a deep stack training smoothly and needing a careful warmup to converge at all.

**Weight tying.** The input embedding matrix and the output projection are the same tensor.
Same vocabulary, same space — and it saves a meaningful fraction of the parameters at this
scale.

## [2:11] The baselines nobody shows

> **On screen —** the perplexity comparison

Here's the evaluation, and here's where this differs from most demos.

The measure is perplexity on held-out text — roughly, how many characters the model is
effectively choosing between at each step. Lower is better.

My model: **4.555**.

Is that good? You cannot possibly tell, and that's the point. So here are two baselines.

A **uniform** model, which picks every character with equal probability: perplexity
65. That's just the vocabulary size — it's what "knowing
nothing at all" scores.

A **unigram** model, which knows nothing but how often each character appears in the
corpus — no context, no order, just frequencies: perplexity
27.462.

That second one is the honest bar. Beating uniform is trivial. Beating unigram means you've
learned something about *sequence*.

My model is 6.0 times better than unigram.

Now 4.55 means something. Without those two numbers it was
decoration.

## [3:14] The mistake I made and left in the record

> **On screen —** the parameter count assertion in the source

A small confession that I think is worth including.

An earlier version of my own documentation said this model had about 2.7 million parameters.
The real number is 1,785,408. I'd written the docstring from a config I
later changed, and then I didn't recount.

Which is exactly the failure mode this whole repository is built to prevent — prose drifting
away from reality because nobody re-derived it.

The fix isn't "be more careful." The fix is that the expected parameter count is now derived
from the config constants and asserted at runtime. If the architecture changes and the count
doesn't match, the pipeline raises an error instead of producing a document that's quietly
wrong.

That's the general principle here: don't rely on remembering. Make the machine check.

## [4:11] What it can and cannot do

> **On screen —** the training curve and attention spans

Being clear about the limits.

This model learned character-level structure. Spelling, word shapes, the rhythm of dialogue,
speaker names followed by colons, line breaks in roughly the right places. At
1,785,408 parameters on one corpus, that is genuinely what you'd expect.

It has not learned meaning, facts, or long-range coherence. Read a sample past a couple of
lines and it wanders.

The best validation loss came at step 2,200, with training loss at
1.3091 against validation 1.5163. That gap is the model
beginning to memorise, which is why the checkpoint that gets evaluated is the best-validation
one rather than the last one.

The value here isn't the model. It's that every component is visible and modifiable, and
you can trace exactly what each one does.
